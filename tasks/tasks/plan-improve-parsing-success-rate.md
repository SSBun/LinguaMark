# 规划提高内容解析成功率

Status: Completed (2026-08-31 15:28)
Kind: Plan

## Scope

- 包含：当前分析区域内的文本发现连续性、句子级响应恢复、失败隔离、有限重试、部分渲染和句子级进度。
- 不包含：默认预先解析整篇文章、更换模型供应商、降低现有句法／翻译校验强度、增加新的用户设置或外部依赖。

## Target
- [x] T1: 任一模型响应中的缺句、坏句或无效角色只影响对应句子；同一文本块中已通过严格校验的其他句子仍能渲染。
- [x] T2: 普通成功路径每个文本块仍只发起一次模型请求；每个文本版本的自动模型请求总数最多为两次。
- [x] T3: 当前视口、预加载区、快速滚动经过区和分析期间新插入或原位更新的合格文本最终都会进入队列；未变化文本不会重复请求。
- [x] T4: 进度和日志分别报告发现、校验成功、渲染成功与失败的句子数，不再用文本块成功或 Range 数冒充句子解析成功。
- [x] T5: 主内容过滤、Twitter 专用范围、代码块／隐藏文字排除、API Key 隔离、翻译开关和现有标记交互保持有效。

## Decisions

- 采用“文本块首轮请求 + 句子级恢复”的单一管线：首轮仍按现有文本块请求，避免把正常路径改成逐句请求；解析器按句子 ID 独立校验并保留有效结果。
- 首轮响应存在缺失或无效句子时，第二次请求只要求修复未通过的句子，同时保留完整段落上下文；若首轮是网络、超时、截断或非法 JSON，则第二次请求重试整个文本块。
- 每个文本版本共用两次模型请求预算。第二次仍未通过的句子记录为显式失败，不能阻塞兄弟句子，也不能继续自动循环请求；用户重新发起分析时才重置预算。
- 严格校验下沉到单句边界：未知词元、非连续角色、缺失翻译和非法句型仍不得渲染；不得通过放宽 Schema、伪造角色或把完整句静默降为 fragment 来提高数字。
- 本地分句结果增加稳定句子 ID 与原文起止位置；模型仍不提供偏移。渲染按本地位置逐句验证并应用，因此部分成功不再要求注解覆盖整块原文。
- 文本目标状态改为 `目标 ID + 版本 + 原文快照`。同一 DOM Text 节点内容变化时递增版本；Background 按目标和版本去重，旧版本响应只能被丢弃，不能覆盖新内容。
- 保留视口加预加载模式，不默认扫描整篇文章。滚动扫描覆盖上次与本次分析区域的并集；一个合并调度器同时接收滚动和 DOM 文本变化通知，避免快速跳转和异步插入形成空档。
- 主内容根优先级改为 `main/[role=main]`、其内文章、全局 `article`、最后 body，避免无关 article 抢占真正主内容；仅明确的标题、标签和交互文本允许 fragment，普通 div 正文不再因标签类型自动放宽。
- 进度以句子为事实源，分别统计 discovered、valid、rendered、failed；文本块统计只保留为调度诊断。显示层关闭不改变 rendered 的语义，另行记录可见 Range 数。
- 不新增依赖、缓存层或可配置重试系统；若后续日志证明输出截断仍频繁，再单独规划长文本预分块。

## Plan

1. 建立句子级结果契约：为本地分句保存 ID、起止位置和成功／失败状态，并让响应解析返回有效句子与结构化失败原因，而不是遇到首个坏句即抛弃整块。
2. 将现有一次整块纠错改为共用两次预算的定向恢复：合并首轮有效结果与第二轮修复结果，保证正常路径请求数不变，并对网络类失败使用同一预算。
3. 让渲染计划按本地句子位置接受部分结果；逐句校验原文版本、应用重要度／角色／翻译，并把实际句子应用数返回 Background。
4. 将 Content 和 Background 的去重状态升级为文本版本状态机；失败完成、内容原位更新、旧响应到达和用户重新分析都有唯一、可观察的状态转换。
5. 统一滚动与 DOM 变化扫描，补齐两次滚动位置之间的文档区域，并修正主内容根优先级和 fragment 边界，同时保留现有排除规则。
6. 更新 Popup、悬浮卡片与结构化日志的句子级统计；验证一个坏句不影响兄弟句、第二次修复成功／失败、网络重试封顶、快速滚动、动态插入、Text 节点复用、旧响应、主内容选择和显示层关闭场景。
7. 执行阶段运行类型检查、构建和差异检查；新增聚焦检查用例，项目测试套件仅在用户明确授权后运行。

## Result

- T1: 新增逐句可恢复校验、稳定本地句子位置和部分 RenderPlan；坏句进入 failedSentences，兄弟有效句继续生成 DOM Range。
- T2: Background 首轮全有效时 unresolvedIds 为空；仅缺失／无效句或响应级失败使用第二次请求，代码路径不存在第三次自动请求。
- T3: Content 以目标 ID、文本版本和快照去重，滚动扫描取前后区域并集，MutationObserver 合并发现新增与原位更新文本，旧版本渲染被拒绝。
- T4: Background、Popup 与学习卡片现分别传递和显示 discovered、valid、rendered、failed 句数；Range 只作为 rangeCount 诊断。
- T5: 保留 Twitter 范围、隐藏／代码块／UI 排除、Background API Key 边界、翻译设置与 CSS Highlight 交互；类型检查和构建通过。
